# Shared Resources & Configurations

> **Scope:** This directory acts as the centralized repository for shared configurations, exploratory workflows, common utility scripts, and local data persistence. It serves as the integrative foundational layer aligning the Machine Learning pipelines, Data Platform analytics, and Exploratory Data Analysis (EDA).

---

## Overview

The `shared` environment ensures cross-functional parameter consistency and stateless data hand-offs. It explicitly hosts the paramount operational configuration file (`params.yaml`) utilized to dynamically orchestrate hyperparameter boundaries, temporal training splits, and LightGBM engine semantics. 

Following architectural streamlining, legacy strict state-locking (formerly executed via DVC) has been deprecated. The system now operates on lightweight local staging for deterministic data partitions (`.parquet` files) while deferring primary artifact lineage and model registry tracking exclusively to MLflow.

---

## Directory Architecture

```text
shared/
├── params.yaml                 ← Centralized tunable parameters targeting ML phases (prepare, train, tune)
├── data/
│   ├── data_raw/
│   │   └── test.csv            ← Static Kaggle evaluation indices (inference dependency constraint)
│   └── processed/              ← Intermediate cached outputs generated by ML data preparation vectors
│       ├── train.parquet       ← Materialized temporal training distribution
│       ├── valid.parquet       ← Materialized temporal validation distribution
│       └── test.parquet        ← Retained evaluation target sets
├── outputs/
│   └── metrics.json            ← Local snapshot persistency for isolated training evaluation metrics
├── utils/
│   └── utils.py                ← Reusable EDA analytical utilities (e.g., rolling aggregations, EWMA, plotting)
└── notebooks/                  ← Exploratory Jupyter computational narratives
```

## Global Parameters Reference (`params.yaml`)

The `params.yaml` configuration dictates the deterministic behavior of the upstream ML pipeline execution environments.

### Phase 1: `prepare`

| Analytical Parameter | Instantiated Value | Functional Target |
|---|---|---|
| `cutoff_date` | `"2014-08-01"` | Imposes the definitive temporal demarcation for chronological Train/Validation dataset splitting. |

### Phase 2: `train`

Dictates the structural topology to be assumed by the final LightGBM Regressor.

| Topological Parameter | Operational Effect / Instantiated Value |
|---|---|
| `objective` / `metric` | Target evaluation methodology (`regression`, `rmse`). |
| `boosting_type` | Algorithm class (`gbdt`). |
| `num_leaves` | Defines terminal nodes dictating granular tree complexity (`127`). |
| `learning_rate` | Gradient descent optimization step magnitude (`0.0125`). |
| `feature_fraction` | Random column subsampling proportion to mitigate high variance (`0.804`). |
| `bagging_fraction` | Random row sampling frequency scaling (`0.903`). |
| `lambda_l1` / `lambda_l2` | Ridge and Lasso systematic regularization (`7.33e-08`, `0.00357`). |
| `max_depth` | Explicit arbitrary limit restricting exhaustive node expansion (`11`). |
| `n_estimators` / `early_stopping` | Computational iteration limitations preventing indefinite epoch cycles (`1000` / `50`). |
| `random_state` | Heuristic seed establishing evaluation reproducibility (`2025`). |

### Phase 3: `tune`

Controls the stochastic boundaries applied within the Optuna hyperparameter topology.

| Constraint Parameter | Evaluated Operational Context |
|---|---|
| `n_trials` | Limits the maximum exploration evaluations of the Optuna Engine (e.g., `50`). |
| `timeout_sec` | Execution duration threshold (A value `0` implies disabled). |
| `study_name` | Standardized tagging mapping internally to the MLflow experiment registry (`lgbm_global_optuna`). |

## System Integration Map

| Architectural Node | Upstream/Downstream | Functional Contract |
|---|---|---|
| **ML execution routines** | `ml/scripts/*` | Consumes `params.yaml` parameters explicitly configuring temporal splits and inference structures. |
| **Data Platform Extraction** | `shared/data/processed/` | Acts as the local staging transition volume linking data fetching (`prepare_data.py`) with learning vectors (`train.py`). |
| **Exploratory Analytics** | `utils/utils.py` | Supplies statistical interpolation protocols rendering uniform feature engineering inside `notebooks/`. |
